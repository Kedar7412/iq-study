# IQ Study MVP: auth + tenant-isolation fix pass (v2)

The fix pass closed both blocking issues from v1 and the two product-quality gaps. The ingestion and results endpoints (`/api/upload`, `/api/analyze`, `/api/books/[bookId]`) now verify the session server-side and return 401 to anonymous callers, matching the study/onboarding routes. Book ownership moved into the store: `StoredBook` carries a required `userId` set at upload, and `get`/`list`/`saveAnalysis` all take a `userId` so a non-owner resolves to `undefined` and every content route (books, analyze, both study routes) returns 404 to anyone but the uploader. The questionnaire now rejects partial submissions with a 400, and curriculum overlap is a graded `[0,1]` score instead of binary. Watch for: the fixes are real and test-guarded — the only remaining items are minor (an unused `list()` method with no index page, and no test asserting `/api/upload` itself rejects anonymous callers) (confirmed).

**Verdict**: APPROVED

## High-level view

The auth asymmetry from v1 is gone. All three previously-public content endpoints call `getSession()` and 401 before touching the store, so the intended "verify server-side" posture is now uniform across the API. The `proxy.ts` matcher was deliberately left gating pages only, which is the correct call — a blanket `/api/*` gate would break the public `login`/`register` routes, and each content route now self-gates anyway.

Tenant isolation is enforced at the store boundary rather than sprinkled across callers: `InMemoryBookStore.get`/`saveAnalysis` return `undefined` when `book.userId !== userId`, so a route that forgets to pass ownership can't accidentally leak a book — it gets nothing. Every content route passes `session.sub`, and a non-owner lands on the same 404 as a missing book, which avoids confirming that someone else's `bookId` exists. The `routeAuth.test.ts` suite exercises this end-to-end against the real store singleton, and it genuinely fails (3 ownership tests) when the `userId` check is stripped out — the guard is not decorative.

The questionnaire fix makes `validateAnswers` require an answer for every item before scoring, so a truncated client can no longer produce a lopsided profile that silently drives every downstream adaptation; the onboarding route surfaces the thrown message as a 400.

Curriculum overlap is now graded: an exact topic match scores 1.0, an all-words-but-not-a-listed-topic concept approaches but never reaches a full match (capped at `PARTIAL_MATCH_CEILING = 0.9`), and a single coincidental word contributes only a small fraction. Both `analyzeBook` (as an additive boost) and `generateQuestions` (as a weighted term) consume the same function, and `conceptMatchesCurriculum` was kept as a boolean view (`score > 0`). Everything stays deterministic under the mock, and the full suite (79 tests), typecheck, lint, and build remain green keyless.

### Auth guard now uniform, and the store owns tenant isolation

The three previously-public routes each start with the same check before any work:

```ts
const session = await getSession();
if (!session) {
  return NextResponse.json({ error: "Not authenticated." }, { status: 401 });
}
```

Ownership is not re-checked in the routes; it's delegated to the store:

```ts
async get(bookId: string, userId: string): Promise<StoredBook | undefined> {
  const book = this.books.get(bookId);
  if (!book || book.userId !== userId) return undefined;
  return book;
}
```

`saveAnalysis` applies the identical `existing.userId !== userId` gate, so a non-owner can neither read nor mutate another user's analysis. Upload stamps ownership from the session (`userId: session.sub`) rather than trusting any client field. Because the guard lives in the store, the study `grade`/`next` routes that pass `session.sub` inherit isolation for free — the v1 diff shows the exact change from `get(bookId)` to `get(bookId, session.sub)`.

The non-owner path returns 404, not 403: a 403 would confirm the `bookId` exists, so collapsing "not yours" into "not found" avoids leaking existence.

### The ownership tests would fail if the check were removed

`routeAuth.test.ts` mocks only `getSession` and drives the real in-memory store singleton, seeding books directly, so it exercises the actual enforcement rather than a stub. Replacing `if (!book || book.userId !== userId)` with `if (!book)` flips the three "non-owner gets 404" cases (books, analyze, study/next) to failures — verified by running it. The isolation guarantee is pinned by a test that tracks the real behavior, not a mirror of it.

The gap: there's no case asserting `POST /api/upload` rejects an anonymous caller. Upload is the endpoint that assigns ownership, so it's the one most worth a regression test, and it's the only content route the suite doesn't cover.

### Graded curriculum overlap replaces the binary signal

`curriculumOverlapScore` returns 1.0 for an exact topic match, `matched/total * 0.9` for a partial word-level match, and 0 for none:

```ts
if (terms.has(normalized)) return 1;
const words = normalized.split(" ").filter(Boolean);
const matched = words.filter((word) => terms.has(word)).length;
if (matched === 0) return 0;
return Number((matched / words.length * PARTIAL_MATCH_CEILING).toFixed(4));
```

Both scoring sites consume it: `analyzeBook` as `CURRICULUM_BOOST * score` (additive, capped at importance 1.0) and `generateQuestions` as `CURRICULUM_WEIGHT * score` inside the probability. A two-word concept sharing one syllabus word now scores ~0.45 instead of jumping to a full match, so a one-word coincidence no longer ties a full-topic match at the top of the ranked list. The ceiling keeps an all-words-present concept just below an exact listed topic, preserving a strict ordering the tests assert directly.

### Partial-questionnaire submissions now rejected

`validateAnswers` first rejects unknown question/option ids (so the error is specific), then requires every questionnaire item to be answered, listing the missing ids. The onboarding route maps the thrown message to a 400, so a client that posts a subset no longer receives a skewed-but-accepted profile that would then drive every downstream adaptation.

### Product flow against the pitch

End to end the MVP now matches the described product: log in, answer the onboarding questionnaire to get a VARK-style profile, upload a book, analyze it against a supplied curriculum into ranked "high probability" questions, and study them through a profile-adapted SM-2 loop with per-concept mastery and a concept graph. The per-user promise ("*your* book, *your* brain") is now actually enforced. The one place the product story outruns the code is the library view: `list(userId)` exists and is correctly scoped, but nothing calls it and there's no index page, so a user can't see their own set of uploaded books — they need to hold the `bookId`. In-memory persistence across serverless invocations remains the documented, accepted MVP limitation.
